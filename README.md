## ðŸš€ The Core Problem & Our Innovation

Conventional reconciliation systems that naively use Large Language Models (LLMs) to perform matches introduce **hallucination risks**, violate compliance requirements (as LLM predictions lack deterministic audit trails), and represent a single point of failure when third-party APIs time out or go offline.

**LedgerLens** resolves this by placing a **strict deterministic safety boundary** around the AI.
1. **Deterministic matching algorithms** own all financial decisions and write immutable records to the ledger.
2. **AI operates strictly as a read-only advisor** post-reconciliation, using sandboxed tools to investigate and explain exceptions.

## ðŸ›¡ï¸ We Attacked Our Own Reconciler

Instead of tuning our algorithms to look good on select tests, we subjected LedgerLens to active **self-adversarial evaluation**:
1. **Initial Vulnerability:** Early benchmarks on Seeds `45` and `103` exposed an *unsafe auto-match*. Timing delays generated by date corruption shifted clearings by 1 day, which still satisfied the business clearance timing window of rule `V003`.
2. **Contamination Drops:** Shared-evidence batch contamination caused clean records within corrupted settlements to fail balancing checks, dropping recall scores to ~55%.
3. **The Hardening:**
   - **Generator Timing Invariant:** Modified date mismatch generator to shift dates strictly outside the clearing window, making corruptions mathematically unmatchable.
   - **Contamination-Aware Evaluation:** Hardened the evaluator (Model B) to expect `HUMAN_REVIEW` outcomes for clean payments associated with corrupted settlement packages.
4. **The Outcome:** Rerunning independent partitions proved that **unsafe auto-matches fell to exactly 0.0000**, while **recall rose to 98%â€“99%**.

## âš¡ Quick Start

### 1. Environment Configuration
Copy the environment variables template and set your postgres credentials:
```bash
# Root env template (for Docker database)
cp .env.example .env

# Backend env template (FastAPI database config)
cp backend/.env.example backend/.env
```

### 2. Backend Setup
```bash
cd backend
python -m venv .venv

# Windows
.venv\Scripts\activate
# macOS/Linux
source .venv/bin/activate

pip install ".[dev]"
uvicorn app.main:app --reload --port 8000
```
- API Docs: `http://localhost:8000/docs`
- Health check: `http://localhost:8000/health`

### 3. Frontend Setup
```bash
cd frontend
npm install
npm run dev
```
- Console UI: `http://localhost:5173`

### 4. Running Benchmarks
Run the evaluation benchmark across the defined calibration seed partition:
```bash
cd backend
.venv\Scripts\activate
python scripts/run_benchmark.py --config data/synthetic/config_bench_100.yaml --seeds 42,43,44,45,46
```

### 5. Running Tests
Run backend regression tests:
```bash
cd backend
pytest tests/ -v
```
